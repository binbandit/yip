# Adversarial playground campaign, 28 September 2026

The owner authorized a dedicated GitHub playground, the three signed-in GitHub
accounts as simulated collaborators, and bounded real Codex/Claude runs.
All hub databases, runner identities and repositories are disposable fixtures.
The daily-use hub and development server are excluded.

## Coverage plan

| Persona | Workflows and injected failures | Evidence layer |
|---|---|---|
| Solo private project | Assignment, editing, tests, owner review, explicit questions, interrupted sends, private access revoked then restored | Hub/runner integration, browser, private GitHub repo |
| Open source contributor | Fork PR, distinct author and maintainers, changes requested, correction, stale head, draft/closed/merged state, repeated publication | Real GitHub plus connector contract |
| Platform team | Two required approvals, CODEOWNERS, required checks pending/failing/passing, stale approvals dismissed, multiple questions, crowded engineer/project selectors | Protected public GitHub fixture, hub/runner, browser |
| Recovery | Permission loss during reads, account rotation, ambiguous publication, provider crashes after authorized external writes, hub restart, duplicate delivery | Adversarial HTTP and hub/runner integration |
| Privacy | Project and room revocation during review, artifact download permissions, exact checkpoint authorization | Actual mutual-TLS runner endpoints |
| Real engineers | Codex editing and denial/resume, Claude permission round trip, autonomous author/reviewer work through yip | Installed provider CLIs and isolated hub |
| Daily workspace | Repeated assignments in one database, restarts, queued input, cancellation/retry, corrected documents, recall, backup restoration | Persistent hub/runner campaign plus real-provider continuation |

This matrix targets representative workflows and dangerous state transitions.
It is not a claim to enumerate every possible scenario. Large-team fixtures
exercise multiple engineer scopes and GitHub protection, not enterprise SSO,
organization teams or multi-human tenancy (which yip does not yet implement).

| 1 | Explicit answer to the second threaded question resolved the first | Exact targets win; ambiguous replies resolve none |
| 2 | Revoked reviewer still downloaded a private document | Every download rechecks current room/project access |
| 3 | A bundle ID mentioned in ordinary chat granted private-source download | Only explicit `restoreArtifactId` grants restoration access |
| 4 | Crash after authorized shell push retried automatically | Potential external effects require explicit retry, including after restart |
| 5 | Removed access still allowed new or pending command approvals | Request and owner-decision paths recheck live scope |

| 7 | Pending GitHub review marker falsely confirmed publication | Draft markers are ignored; submitted/dismissed history remains evidence |
| 8 | Later-page permission loss erased already-observed failing checks | Definite failures remain; incomplete passing evidence stays unknown |
| 9 | Credential rotation changed actor between eligibility check and POST | Each publication/reconciliation snapshots one credential |
| 10 | Conversation dispatched despite provider's unsupported read-only mode | Work waits with the actual limitation and resumes after capability changes |
| 11 | Keyboard-selected engineer scrolled outside a crowded mention menu | Active option stays visible |
| 12 | Mobile project picker extended beyond the page | Menu is bounded by available viewport space |
| 13 | Empty-room greeting listed every engineer in a large team | Greeting remains compact |
| 14 | Editing an unsent room message lost selected project | Original routing context is preserved |
| 15 | Editing an unsent thread message lost structured mentions | Selected engineer remains a structured recipient |
| 16 | Confirmed message remained unsent after HTTP response loss | Canonical event/page delivery clears persisted retry state |

Security, routing and recovery fixes have focused regressions and positive
controls. Rendering and interaction fixes were reproduced in system WebKit.

The publication audit also removed an unverified cached viewer identity from

## Concurrency and recovery

The new integration cases cover 19 permission, privacy, question and recovery
scenarios plus three concurrency scenarios. The concurrency set passed ten
ordinary repetitions and two race-enabled repetitions, with no data races:

- 32 concurrent duplicate sends, then 32 retries after restart: exactly one
  message, dispatch and attempt.
- 24 distinct requests across three public/private rooms and mixed threads:
  correct immutable reply destinations.
- Two runners sharing one account, with 16 cancellations and 32 retries:
  one active lease and exactly one accepted retry.

The ten ordinary repetitions exercised 1,360 burst requests plus controls.
These are bounded correctness tests, not a production capacity benchmark.

The final scope audit added 18 actual permission journeys for equivalent
checkout, directory, environment, Git remote and GitHub repository selectors,
including positive controls for the assigned checkout. The publication audit
added fault-injected hub/runner/bridge scenarios for definite failure followed
by successful retry, ambiguous responses and delayed visibility, concurrent
calls, outcome-save failure, and a late response racing a saved confirmation.
The five publication regressions and two existing identity/webhook scenarios
passed together with the race detector.
Two additional upgrade cases reproduced the old failed-canonical/suffixed-retry
layout and passed after repair, including a rotated account that could not see
the previous actor's marker. Confirmed publication is reused; an unknown
publication waits until it can be reconciled.

A separate persistent-workspace campaign kept one database for 12 assignments:
11 reviewed completions and one cancellation, with a single shared account
slot. It exercised two hub/runner restarts, queued clarification while offline,
duplicate answer delivery, document correction and re-review, cross-room
recall, and a database/artifact snapshot containing 38 verified blobs. All four phases
passed, followed by three complete ordinary repetitions and one complete
race-enabled repetition with no race reports. This tests repeated work and
durability, not a multi-day unattended soak.

## Real-provider evidence

Codex `0.157.1` passed its real MCP/edit/permission-denial/resume smoke test.
Claude Code `2.1.283` passed flag compatibility and MCP/Bash approval tests.
Both used existing subscription sign-ins. No login configuration or allow-rules
were changed.

The first team attempt exposed the scheduler's unsupported-conversation bug.
The next used Claude for intake, Codex for implementation and Claude for
review: it reached a failing regression, fix, passing exact-head checks and
independent reviewer checks, then correctly paused when the reviewer requested
an outside-workspace temporary Python helper. General review instructions now
explain supported existing checks and read-only inspection, and require missing
verification to be requested from the author rather than skipped.

The final real campaign passed in 113.9 seconds. Claude handled intake and
delegated to Codex, which recorded the red regression, fixed and published
`d098f10e59cef06d0503b3423a53f76c4422647c`, and recorded passing checks on
that exact revision. Claude independently checked and approved it. All five
provider runs (including resumed author work and the later recall) finished
naturally. A separate Claude conversation in Engineering recalled the actual
saved work record, regression coverage and approved revision. Nothing was
pushed, merged or deployed by these real engineers.

The [real campaign result](2026-09-28-real-team.json) preserves both assertions.
The earlier blocked attempts remain part of the evidence and are not counted
as successful runs.

The same real workspace then passed a second daily-use cycle in 144.3 seconds.
A restart preserved the first approved result. Claude delegated an independent
feature to Codex; the harness cancelled Codex after an actual file edit and
waited for confirmed termination. Input to cancelled work returned 409 without
leaving a message. Explicit retry received a fractional-timestamp clarification,
finished the feature and received independent Claude approval of
`46cd64c657b875ff8014c14ec369b5e04549ea49`. Four independently executed behavior
cases passed. The earlier feature's source files were unchanged. A final
restart retained both reviewed results, conversation history and reviewer
records. See [the daily-cycle record](2026-09-28-real-daily.json).

An independent audit tightened the verifier and rechecked the saved evidence:
the edit succeeded, the confirmed cancelled attempt was directly resumed on
the same machine, workspace and provider session, and the retained helper's
Git blob matches the approved revision. The workspace is clean at that exact
head; behavior checks execute its committed source. Both accepted reviewer
records match in full. Negative controls reject failed edits, fresh sessions,
different workspaces, altered files, wrong heads and missing/changed records.
This proves same-machine workspace retention, not cross-machine recovery.

The follow-up relationship preserves work history; it does not implicitly
inherit an unpublished prior patch. The second assignment deliberately started
from the repository's default branch and produced a separate local result.

The real fixture also passed the actual `yip backup` and `yip restore`
commands into a new directory. The restored hub started on separate loopback
ports, accepted the existing owner's login, and served both completed approved
revisions and both reviewer records unchanged. The backup verified 11 unique
artifact blobs and all recorded table counts. No runner or provider was
started during this restore check; the temporary hub was then stopped.

## Browser evidence

All 53 distinct system WebKit journeys passed: the 34 existing workflows,
nine new delivery/team cases and ten stress cases. After the final source
changes, all 19 new cases were rerun together and passed. The full web unit
suite reports 137 passed, zero failed; type checking reports zero errors and
warnings. [Before/after captures](../screenshots/simulation-2026-09-28/README.md)
show the crowded mention menu and mobile project picker at native scale.

Independent review caught one introduced retry-edit regression before final
verification: a missing job cache after reload discarded an unsent message's
assignment. A mounted-app test reproduced it; unknown job IDs are now retained
until fetched terminal state establishes that they are no longer usable.

The installed system Chrome 153 also passed all six Playwright journeys,
including work delivery, keyboard access, search, drawers and mobile layout.
Chromium sandboxing was explicitly enabled. Two stale test selectors were
corrected; this pass found no additional product failure. No browser or
dependency was downloaded. Firefox remains untested.

## Daily-use assessment

The tested local configuration uses Claude for conversational intake and
independent review, and Codex for implementation. It now has direct evidence
for real work, cancellation, retry, review, recall and restart durability, plus
broader scripted recovery, privacy and concurrency coverage. Codex intake and
review remain unavailable under this machine's existing allow-rules; yip now
waits with that reason instead of dispatching an unsupported mode.

This campaign does not establish multi-day unattended reliability, behavior
across two physical machines, reboot under the intended service account, or
Cursor compatibility. Provider versions are newer than the protocol pins.
Cross-machine recovery uses a verified bundle of a published revision;
unpublished edits are retained on the original machine and are not currently
restored from checkpoint records onto another machine. An ambiguous GitHub
publication can require manual remote verification and later reconciliation.
No live hub was migrated, reconfigured or restarted as part of this work.

## Reproduction entry points

- `scripts/simulation/github_playground.py`: explicitly selected real GitHub
  fixture setup and scenario phases; credentials are never saved in state.
- `TestSimulationGitHub`: gated connector observations and publications against
  the exact prepared PR, with explicit expected facts.
- `test/integration/simulation_test.go`: isolated hub, runner, bridge and
  permission/recovery regressions.
- `test/integration/concurrency_simulation_test.go`: concurrent send, restart,
  destination and account-slot checks.
- `test/integration/daily_driver_simulation_test.go`: repeated work, offline
  input, restart durability, document correction and snapshot integrity.
- `test/integration/live_github_test.go`: gated real GitHub publication through
  the actual yip hub/runner/bridge.
- `test/integration/forge_publication_simulation_test.go`: publication retry,
  concurrency, delayed visibility and durable outcome regressions.
- `scripts/simulation/real_team.py --run-real-providers`: bounded real-provider
  team assignment; `--delegate-through-reviewer` handles this machine's Codex
  conversation limitation without changing its permission configuration.
- `scripts/simulation/daily_driver.py --run-real-providers`: continuation of
  the preserved real-team fixture, including cancellation and two restarts.
- `web/tests/webkit/simulation.js` and `simulation-stress.js`: real WebKit
  interaction, interrupted requests, multiple questions and responsive layouts.

GitHub semantics used for the fixtures: [branch protection](https://docs.github.com/en/rest/branches/branch-protection)
and [review publication](https://docs.github.com/en/rest/pulls/reviews).
