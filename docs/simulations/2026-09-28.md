# Adversarial playground campaign, 28 September 2026

The owner authorized a dedicated GitHub playground, the three signed-in GitHub
accounts as simulated collaborators, and bounded real Codex/Claude runs.
All hub databases, runner identities and repositories are disposable fixtures.
The daily-use hub and development server are excluded.

## Coverage plan

| Persona | Workflows and injected failures | Evidence layer |
|---|---|---|
| Solo private project | Assignment, editing, tests, owner review, explicit questions, interrupted sends, private access revoked then restored | Hub/runner integration, browser, private GitHub repo |
| Open source contributor | Fork PR, distinct author and maintainers, changes requested, correction, stale head, draft/closed/merged state, repeated publication | Real GitHub plus connector contract |
| Platform team | Two required approvals, CODEOWNERS, required checks pending/failing/passing, stale approvals dismissed, multiple questions, crowded engineer/project selectors | Protected public GitHub fixture, hub/runner, browser |
| Recovery | Permission loss during reads, account rotation, ambiguous publication, provider crashes after authorized external writes, hub restart, duplicate delivery | Adversarial HTTP and hub/runner integration |
| Privacy | Project and room revocation during review, artifact download permissions, exact checkpoint authorization | Actual mutual-TLS runner endpoints |
| Real engineers | Codex editing and denial/resume, Claude permission round trip, autonomous author/reviewer work through yip | Installed provider CLIs and isolated hub |

This matrix targets representative workflows and dangerous state transitions.
It is not a claim to enumerate every possible scenario. Large-team fixtures
exercise multiple engineer scopes and GitHub protection, not enterprise SSO,
organization teams or multi-human tenancy (which yip does not yet implement).

## GitHub evidence

All **32 live connector scenarios passed**, with observations and explicit
expectations saved in [the machine-readable record](2026-09-28-github.json).
The existing write-enabled contract test passed under `binbandit`,
`sage-smudge` and `WastedHippie`. Three additional scenarios drove publication
through the browser API, hub, paired runner and bridge: missing grant denied,
author approval denied, and authorized distinct reviewer published. These
use scripted provider tool calls and real GitHub.

The private fixture also proved that removing a collaborator causes a real
404, then restoring the invitation restores access. GitHub Actions ran a
deliberately failing unit test and passed the corrected revision. The team
fixture required two distinct approvals, CODEOWNERS and passing checks;
one approval or green checks alone stayed blocked, and new commits dismissed
old approvals. A fork contributor exercised changes requested and approval.

## Concurrency and recovery

The new integration cases cover 19 permission, privacy, question and recovery
scenarios plus three concurrency scenarios. The concurrency set passed ten
ordinary repetitions and two race-enabled repetitions, with no data races:

- 32 concurrent duplicate sends, then 32 retries after restart: exactly one
  message, dispatch and attempt.
- 24 distinct requests across three public/private rooms and mixed threads:
  correct immutable reply destinations.
- Two runners sharing one account, with 16 cancellations and 32 retries:
  one active lease and exactly one accepted retry.

The ten ordinary repetitions exercised 1,360 burst requests plus controls.
These are bounded correctness tests, not a production capacity benchmark.

## Real-provider evidence

Codex `0.157.1` passed its real MCP/edit/permission-denial/resume smoke test.
Claude Code `2.1.283` passed flag compatibility and MCP/Bash approval tests.
Both used existing subscription sign-ins. No login configuration or allow-rules
were changed.

The first team attempt exposed the scheduler's unsupported-conversation bug.
The next used Claude for intake, Codex for implementation and Claude for
review: it reached a failing regression, fix, passing exact-head checks and
independent reviewer checks, then correctly paused when the reviewer requested
an outside-workspace temporary Python helper. General review instructions now
explain supported existing checks and read-only inspection, and require missing
verification to be requested from the author rather than skipped.

The final real campaign passed in 113.9 seconds. Claude handled intake and
delegated to Codex, which recorded the red regression, fixed and published
`d098f10e59cef06d0503b3423a53f76c4422647c`, and recorded passing checks on
that exact revision. Claude independently checked and approved it. All five
provider runs (including resumed author work and the later recall) finished
naturally. A separate Claude conversation in Engineering recalled the actual
saved work record, regression coverage and approved revision. Nothing was
pushed, merged or deployed by these real engineers.

The [real campaign result](2026-09-28-real-team.json) preserves both assertions.
The earlier blocked attempts remain part of the evidence and are not counted
as successful runs.

## Browser evidence

All 53 distinct system WebKit journeys passed: the 34 existing workflows,
nine new delivery/team cases and ten stress cases. After the final source
changes, all 19 new cases were rerun together and passed. The full web unit
suite reports 137 passed, zero failed; type checking reports zero errors and
warnings. [Before/after captures](../screenshots/simulation-2026-09-28/README.md)
show the crowded mention menu and mobile project picker at native scale.

Independent review caught one introduced retry-edit regression before final
verification: a missing job cache after reload discarded an unsent message's
assignment. A mounted-app test reproduced it; unknown job IDs are now retained
until fetched terminal state establishes that they are no longer usable.

## Reproduction entry points

- `scripts/simulation/github_playground.py`: explicitly selected real GitHub
  fixture setup and scenario phases; credentials are never saved in state.
- `TestSimulationGitHub`: gated connector observations and publications against
  the exact prepared PR, with explicit expected facts.
- `test/integration/simulation_test.go`: isolated hub, runner, bridge and
  permission/recovery regressions.
- `test/integration/concurrency_simulation_test.go`: concurrent send, restart,
  destination and account-slot checks.
- `test/integration/live_github_test.go`: gated real GitHub publication through
  the actual yip hub/runner/bridge.
- `scripts/simulation/real_team.py --run-real-providers`: bounded real-provider
  team assignment; `--delegate-through-reviewer` handles this machine's Codex
  conversation limitation without changing its permission configuration.
- `web/tests/webkit/simulation.js` and `simulation-stress.js`: real WebKit
  interaction, interrupted requests, multiple questions and responsive layouts.

GitHub semantics used for the fixtures: [branch protection](https://docs.github.com/en/rest/branches/branch-protection)
and [review publication](https://docs.github.com/en/rest/pulls/reviews).
